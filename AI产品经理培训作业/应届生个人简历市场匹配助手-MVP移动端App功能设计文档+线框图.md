# 应届生个人简历市场匹配助手 — MVP 移动端 App 功能设计文档 + 线框图

> **文档版本**：v1.0（2026-07-27）
> **对应阶段**：MVP（0-3 月）
> **配套文档**：《应届生个人简历市场匹配助手-用户深度研究报告.md》
> **设计原则**：最小集、可上线、可验证
> **目标平台**：iOS 14+ / Android 9+（Flutter 或 React Native 跨端方案）
> **目标屏幕**：iPhone 14 Pro (393×852pt) 为基准；Android 360×800dp 等比缩放

---

## 〇、设计原则（MVP 必须守住）

| 原则 | 含义 |
| --- | --- |
| **少即是多** | 只做"匹配 + 投递反馈"闭环，不做社区、不做内推、不做模拟面试 |
| **每周一次仪式感** | 每周一推送是核心锚点，所有 UI 都要为这个动作让路 |
| **匹配分透明** | 每个岗位都必须显示"为什么推给我"，不允许黑盒 |
| **反馈即学习** | 用户的每一次"不感兴趣 / 已投递"都反哺匹配模型 |
| **首屏价值可见** | 注册后 30 秒内必须看到首批匹配岗位 |
| **Web 兜底** | 简历编辑、投递漏斗等长任务用 Web（小程序/H5），App 只做高频交互 |

## 一、产品定位（MVP）

**一句话**：用 AI 把全国招聘平台上的应届生岗位"每周一次、按人匹配、解释清楚"地推到用户手机上，用户看完确认后由 Web/小程序协助投递。

**不做**：
- ❌ 模拟面试、笔试题库
- ❌ 内推社区、职场社交
- ❌ 雇主端、B 端产品
- ❌ 多语言、海外岗位
- ❌ 复杂的简历模板编辑器（仅基础编辑 + AI 改写）

**MVP 三大闭环**：
1. **简历闭环**：上传 → AI 改写建议 → 用户确认 → 进入匹配池
2. **匹配闭环**：每周一推送 100 条 → 用户浏览 → AI 解释 → 用户标记
3. **投递闭环**：标记"想投" → 生成投递文案 → 跳转原始平台 / 由 Web 协助投递 → 反馈回流

## 二、核心用户场景

| 角色 | 场景 | 关键任务 |
| --- | --- | --- |
| **大三/研二在校生** | 秋招前 3 个月开始准备，每周查看一次推送 | 上传简历、查看 100 条、AI 改写简历、确认投递 |
| **应届毕业班（6-7 月）** | 春招补录期，节奏密集 | 每天查看推送、主动搜索、追踪面试反馈 |
| **考研二战/考公失败**（5-6 月） | 临时求职，简历空白，需要快速补全 | 拍照导入、AI 生成简历、紧急推送 |

**MVP 重点服务第一类**（大三/研二），第二三类为后续扩展。

## 五、核心业务流程

### 5.1 首次注册 → 首次匹配（关键路径）

```
[打开 App]
  └─→ 启动页（Logo + Slogan）
       └─→ 引导页 1：价值主张（"每周 100 条精准匹配"）
            └─→ 引导页 2：信任建立（"AI 解释每个匹配"）
                 └─→ 引导页 3：首月 1 元 CTA
                      └─→ 手机号注册 → 验证码 → 注册成功
                           └─→ 学生认证（可选，立刻享受折扣）
                                └─→ 简历上传四选一
                                     ├─ PDF 导入（解析中 → 字段预览 → 确认）
                                     ├─ 在线填写（10 步引导）
                                     ├─ 拍照识别（OCR → 字段预览 → 确认）
                                     └─ 微信简历导入
                                          └─→ AI 改写建议页
                                               ├─ 接受 / 调整 / 跳过
                                               └─→ 偏好设置（3 步引导）
                                                    └─→ 30 秒内出"首批 5 条匹配"
                                                         └─→ 首页（推荐 Tab）
```

### 5.2 每周一推送 → 投递反馈（核心仪式）

```
[每周一 09:00 本地推送]
  └─→ 打开 App → 首页
       └─→ 顶部 Banner："本周为你匹配 100 条 · 已浏览 X 条"
            └─→ 100 条按匹配分降序
                 ├─ 每条卡片：匹配分 / 公司 / 岗位 / 城市 / 薪资 / AI 解释
                 ├─ 操作：❤️ 想投 / 👎 不合适 / 👀 收藏 / ➡️ 详情
                 └─→ 详情页
                      ├─ JD 全文
                      ├─ 匹配点（关键词高亮）
                      ├─ 你的优势 / 差距
                      └─ 操作：[想去投递] [查看原文] [不合适]
                           ├─ 想投 → 加入"投递台/想投"
                           │     └─→ 投递文案 AI 生成（3 选 1）
                           │          └─→ 跳转原平台 / 标记"已投递"
                           ├─ 不合适 → 加入"投递台/不合适" + 二次确认（"为何不合适"可选反馈）
                           └─ 已投递 → 进入"投递台/已投递" + 状态跟踪
```

### 5.3 简历改写闭环

```
[我的 - 简历]
  └─→ 简历预览
       └─→ AI 改写按钮
            └─→ 加载中（10-30s）
                 └─→ 改写结果对比页（左旧右新，可单条切换）
                      ├─ 每条改写卡片：[原文] [新版] [为什么改] [✓ 接受] [✕ 拒绝] [✎ 微调]
                      └─→ 全部确认后 → 保存为新版本（历史可回滚）
```

```
                ┌──── 想投 ────┐
                │              ↓
[岗位出现] → [未操作]      [已投递]
                │              ↓
                └─── 不合适 ──→ [已归档]
```

| 匹配推送生成 | 后台异步，30s 内首批返回 |
| 列表滑动 | 60fps，无卡顿 |

### 10.2 可用性

- **离线可用**：本地缓存最近一次推送（30 天内可看），离线时显示"上次缓存"。
- **网络异常**：岗位详情支持"复制 JD 文本"作为兜底。
- **无障碍**：动态字号、系统字体、VoiceOver 支持。

### 10.3 安全与合规

- 简历数据**端到端加密**（TLS 1.3 + AES-256）；用户可随时导出/删除。
- 第三方爬取数据**单独标识**字段 `source`，合规审查可追溯。
- 用户主动授权范围：仅读取投递状态 / 仅在用户触发时操作。
- 隐私政策明确"不会自动代投简历"，消除合规争议。

### 10.4 兼容性

- iOS 14+ / Android 9+；
- 屏幕：iPhone SE (320×568pt) 到 iPad；
- 弱网：2G/3G 下保证核心流程（查看已缓存推送）。
